# Brief: a small language model for Design with AI

**From:** Adarsh S (AI-EFFECT Solution Studio) · **Date:** 25 November 2026

## The task

In the AI-EFFECT portal, *Design with AI* turns a plain-English request
("compare control strategies on a heavily loaded test grid") into a workflow
of catalogue services, with their settings filled in. Today it uses
OpenAI gpt-4.1-mini. We want a self-hosted Qwen model that does the same job on
our own GPUs, with OpenAI kept only as a fallback.

It is a **structured-output task, not chat**. The model receives instructions
plus a catalogue of 13 services (about 6,000 tokens) and the user's request, and
must return one JSON object: a short explanation, the chosen services and their
settings, or `workflow: null` when nothing in the catalogue fits. Our validator
checks every answer and gives the model up to two chances to fix mistakes.

## Step 1: measure a standard Qwen model (no training)

```bash
# On the GPU machine: serve the model with an OpenAI-compatible API
vllm serve Qwen/Qwen2.5-7B-Instruct --port 8000 --max-model-len 16384

# From a checkout of the repository (Python 3.12)
cd apps/api
pip install -r requirements.txt
python -m app.design_ai.eval.run_eval --base-url http://<gpu-host>:8000/v1 \
       --model Qwen/Qwen2.5-7B-Instruct --repeat 3 --out results-qwen
```

Please try two sizes (about 7–8B and about 14B, any current Qwen instruct model).
Keep structured output (guided JSON decoding) enabled in vLLM; the runner asks
for a JSON schema and falls back to JSON mode if the server refuses.

## Step 2: fine-tune (only if Step 1 misses the target)

Adarsh will provide `train.jsonl`: a few thousand examples in the standard chat
format (`{"messages": [system, user, assistant]}`), generated by a stronger model
and kept only when our validator accepts them. They use the same instructions
and catalogue format as the portal, and none of them overlap with the test cases.
Fine-tune with QLoRA (or your usual method), then run Step 1's command again.

The catalogue changes over time, so the model should learn to **read the
catalogue in the prompt**, not memorise today's services.

## What we need back

1. **The evaluation reports** (`.md` and `.json` from `--out`) for each model

2. **A model endpoint** we can point the portal at (OpenAI-compatible URL), or

4. **A short note**: GPU used, memory needed, typical response time.

OpenAI only when the validator rejects its answer.
