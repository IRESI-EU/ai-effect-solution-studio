## Failure and continuation policy fixed BEFORE observation

**Quality failures:** a valid safe answer that misses a useful clarification/proposal, an unnecessary question, vague progress, inadequate explanation or a clearly marked but unhelpful reversible assumption. Record the case as failed. Phase I may continue with the next independent baseline under the same phase's remaining approved requests. Phase J may continue only with its already planned next intention when the current valid saved graph/proposal supplies all prerequisites; no extra repair request or unreviewed Apply. If a needed valid proposal/choice is absent, mark dependent steps not attempted and stop that journey. Misleading scientific or execution claims fail correctness and must never be used as authority.

**Hard failures:** accounting/usage uncertainty, model/tier/limit drift, refusal/incomplete or malformed/inconsistent structured output, legacy/execution authority, access or ownership failure, concurrent/contract drift, application edit rejection, unexpected mutation/dispatch, cancellation or timeout. Stop all paid dispatch, retain maximum reservation when usage is unknown, close the active scope and do not activate the other phase. Preserve saved work and prior review. Existing fail-closed guards remain unchanged. No automatic retry, alternate endpoint/model, budget increase or replacement scope.

At normal phase completion close that phase. A quality failure never becomes PASS because later cases succeed; it may only yield additional labelled diagnostics. Hard failure does not permit diagnostic paid continuation. Any request outside this fixed plan, or a later recovery exercise, needs new explicit authority.
