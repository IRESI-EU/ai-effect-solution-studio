# Five-minute local module-parameterisation demo

Use the existing isolated offline instance-settings profile. The operator's local
runbook holds the exact presentation/rehearsal IDs, local URLs, private sign-in
locations and screenshot paths; they are intentionally not copied into this
portable review guide. No additional stack or provider response is required.

| Time | Demonstration and wording |
|---|---|
| 0:00–0:40 | “These are two instances of one approved module. Each has its own contract-pinned settings. This is local software configuration.” |
| 0:40–2:10 | Open the fresh presentation copy at first=1/second=2. Select first and show 1. Select second, change only Maximum topologies to 4, Save draft, acknowledge success, refresh, then show first=1/second=4. Preserve both booleans and all connections. |
| 2:10–3:05 | Show retained real-provider A and B evidence. A proposed second-only settings and was explicitly Applied/Saved. B asked which instance and remains unanswered. Read the retained interaction; send nothing. |
| 3:05–4:10 | Open an existing historical algorithm result. Distinguish submitted/effective settings and observed algorithm consumption from today's edited saved design. “This older run has recorded evidence; the new limit-4 copy has not executed.” |
| 4:10–5:00 | Show the draft review dependency chain and validation record. Ask reviewers to inspect registry/transport compatibility, identity, and saved-setting behavior. AIE-18 remains In Review; production compatibility is unverified. |

Prepare the live manual flow on a separate disposable rehearsal copy. Leave the
actual presentation copy at 1/2 until the presentation. The rehearsal should end
at 1/4 after normal Save and refresh. Do not alter the existing verification
solutions, answer the retained clarification, change allowances or submit a run.

Use existing private reviewer credentials through normal sign-in. Do not print,
publish, reset or paste passwords into the runbook. Separate local hostnames or
cookie scopes prevent one profile's login from replacing another profile's session.

Fallback: show the already-captured Builder setting screenshots, the retained
provider proposal/clarification screenshots and the historical evidence screenshot.
Label them as retained screenshots rather than a live operation. If a live profile
is unavailable, use the read-only walkthrough; do not restart unrelated services,
create another stack or infer new execution results.
