# Targeted instance editing and Builder viewport

The conversation receives approved instance labels/IDs, settings and typed contract
metadata, not raw graphs, run inputs, environment, artifacts or unrelated history.
It must identify a unique instance, or ask which one. A valid proposal changes
only supported values on existing instances, pins the contract and base revision,
and leaves the current draft untouched until explicit Apply. Save is a separate
authorized action. The review shows before/after values and unchanged peers.

Saved workflows fit the Builder canvas on initial load. Panning/zooming survives
inspector selection and resizing; explicit Fit workflow restores a whole-graph
view. Independent copied instances preserve supported flags and graph connections.

## Retained provider evidence (not rerun for publication)

Two bounded real-provider attempts used the normal application/provider path on
independent revision-0 drafts initially at limits 1/2. A precise second-step prompt
produced a validated second-only 2-to-4 proposal; explicit Apply, Save, reload and
Builder inspection confirmed first=1/second=4. An ambiguous prompt asked which
step, with edits=[], no proposal and no content/revision change. It was unanswered.
These two observations are narrower than a general model-quality claim.

The immutable local task checkpoint and one-time audited 10-to-12 count amendment
remain exhausted at 12/12; no paid request is authorized for publication or demo.
The amendment CLI supports only the narrow existing open ten-call/USD0.10 policy,
with explicit identity/hash, attribution, authorization, dry-run, atomic policy/audit
and exact checkpoint binding. It cannot change money or reopen a closed ledger.
New ledgers are never silently substituted. Disposable tests exercise rollback,
conflicts, monetary/task limits and stopping at the amended count ceiling.

The exported verification_guard.py is exactly the tested middleware body from the
local-only live profile; it blocks submissions and permits each prepared case
once. The private launcher, preparation accounts, contexts, raw responses and
runtime exports are retained locally and intentionally not published. The product
does not enable this middleware by default. Passive provider audit logging is
disabled by default and records only redacted visible output plus usage, never
hidden reasoning or request context.

The sanitized demo runbook and validation record accompany these changes. No
new algorithm run, independent usability study or production rollout is claimed.
